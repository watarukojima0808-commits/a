# 日経225 デイトレ銘柄スクリーナー

日経225構成銘柄の日足データから、当日のデイトレードに向いた銘柄をスコア順に抽出します。
寄り付き前（8:45頃）に実行し、前営業日終値までのデータで当日の候補を絞り込む想定です。

## セットアップ

初回のみ、構成銘柄リストを日経公式から取得してください（定期入れ替えがあるため、数ヶ月に一度は実行推奨）。

```bash
python nikkei_daytrade.py --update-list
```

リポジトリには `data/nikkei225.csv` にスナップショットが同梱されていますが、
入れ替えが反映されていない可能性があるため、上記の更新を先に実行するのが確実です。

## 使い方

```bash
# 上位10銘柄をターミナルに表示
python nikkei_daytrade.py

# 上位15銘柄、ATR2%以上に絞り、レポートを reports/ に保存
python nikkei_daytrade.py --top 15 --min-atr 2.0 --out-dir reports

# 結果をGmailで自分宛に送る
python nikkei_daytrade.py --out-dir reports \
  --gmail-from you@gmail.com --gmail-to you@gmail.com \
  --gmail-password 'xxxx xxxx xxxx xxxx'
```

### オプション

| オプション | デフォルト | 説明 |
|-----------|-----------|------|
| `--top` | 10 | 表示する上位銘柄数 |
| `--min-atr` | 1.5 | ATR(14)の下限（%）。値幅の出ない銘柄を除外 |
| `--min-turnover` | 20 | 20日平均売買代金の下限（億円）。板の薄い銘柄を除外 |
| `--min-price` | 500 | 株価の下限（円） |
| `--max-price` | 0 | 株価の上限（円、0で無制限） |
| `--out-dir` | なし | Markdownレポートの保存先。`YYYY-MM-DD.md` で出力 |
| `--workers` | 6 | 並列取得数 |
| `--codes-file` | `data/nikkei225.csv` | 銘柄リストCSV（`code,name` 形式） |
| `--update-list` | — | 構成銘柄リストを更新して終了 |

## スコアの内訳（100点満点）

デイトレードで利益機会があるかどうかを、4つの観点で採点しています。

| 配点 | 指標 | 考え方 |
|------|------|--------|
| 40点 | ATR(14) / 株価 | 値幅がなければ利益機会がない。4%以上で満点 |
| 25点 | 前日出来高 / 20日平均 | 出来高急増は当日も値動きが続くサイン。2.5倍で満点 |
| 20点 | 20日平均売買代金 | 板が厚いほど約定が滑らない。1日100億円で満点 |
| 15点 | 5日騰落率の絶対値 | 上下どちらでも「動いている」銘柄を評価。8%で満点 |

上昇・下落の方向は問いません。デイトレでは空売りも使えるため、
「どちらでもいいから動いている」ことを評価する設計です。

## 毎朝自動で実行する（GitHub Actions）

`.github/workflows/nikkei-daytrade.yml` を同梱しています。GitHubのサーバーが平日の朝に実行するため、
自分のPCの電源が入っている必要はありません。publicリポジトリなので無料枠の消費もありません。

### 設定手順

**1. ワークフローをデフォルトブランチに置く**

GitHubの仕様上、スケジュール実行は**デフォルトブランチにあるワークフローしか動きません**。
このブランチをデフォルトブランチにマージしてください。

**2. Gmailアプリパスワードを取得する**

通常のGmailパスワードでは送信できません。2段階認証を有効にしたうえで、
[Googleアカウントのアプリパスワード](https://myaccount.google.com/apppasswords) で16桁のパスワードを発行します。

**3. GitHub Secrets に登録する**

リポジトリの Settings → Secrets and variables → Actions → New repository secret で3つ登録します。

| Secret名 | 値 |
|----------|-----|
| `GMAIL_FROM` | 送信元のGmailアドレス |
| `GMAIL_TO` | 受信したいメールアドレス |
| `GMAIL_PASSWORD` | 手順2で発行した16桁のアプリパスワード |

Secretsは暗号化され、ログにも表示されません。publicリポジトリでも他人から読み取られることはありません。

**4. 動作確認する**

Actions タブ →「日経225 デイトレ候補」→ Run workflow で手動実行できます。
スケジュールを待たずにメールが届くか確認してください。

### 実行タイミング

平日 **8:20 JST**（UTC 23:20）に設定しています。8:45ではなく8:20にしているのは、
GitHubのスケジュール実行が混雑時に5〜20分ほど遅延することがあるためで、
寄り付き（9:00）までに確実にメールが届くようにするための余裕です。

早すぎる・遅すぎる場合は `.github/workflows/nikkei-daytrade.yml` の `cron` を調整してください。
**UTC指定**なので、JSTから9時間引いた値を書きます（曜日も前日にずれます）。

### 実行結果の保存

毎回のレポートは `reports/YYYY-MM-DD.md` としてリポジトリにも自動コミットされます。
過去の選定結果が残るので、後から「このスコアは当たっていたか」を検証できます。

### 注意事項

- **祝日も実行されます。** 日本の祝日判定は入れていないため、休場日には前営業日と同じ内容のメールが届きます
- **60日間リポジトリに動きがないと、GitHubはスケジュール実行を自動停止します。** 毎日のレポート自動コミットで動きは発生しますが、確実に防げる保証はありません。しばらくメールが来ないと感じたらActionsタブを確認してください
- **Yahoo Finance がクラウドのIPを制限する可能性があります。** 取得成功率が60%を下回るとワークフローは失敗し、GitHubから通知メールが届きます。頻発する場合は下記のPC実行に切り替えてください

## PCで自動実行する（GitHub Actionsを使わない場合）

### macOS / Linux（cron）

`crontab -e` で以下を追加します（平日のみ、8:45に実行）。

```cron
45 8 * * 1-5 cd /path/to/repo && /usr/bin/python3 nikkei_daytrade.py --out-dir reports >> screener.log 2>&1
```

cronはOSのローカルタイムで動くため、マシンのタイムゾーンがJSTになっていることを確認してください（`date` で確認）。

Gmail通知も使う場合は、パスワードをcronの行に直接書かず環境変数で渡してください。

```bash
GMAIL_FROM=you@gmail.com
GMAIL_TO=you@gmail.com
GMAIL_PASSWORD=xxxxxxxxxxxxxxxx
45 8 * * 1-5 cd /path/to/repo && /usr/bin/python3 nikkei_daytrade.py --out-dir reports >> screener.log 2>&1
```

`--gmail-from` などのオプションでも指定できますが、その場合は同じマシンの他ユーザーから
プロセス一覧（`ps`）でパスワードが見えてしまう点に注意してください。

### Windows（タスクスケジューラ）

1. タスクスケジューラを開き「基本タスクの作成」
2. トリガー: 毎日 8:45（詳細設定で平日のみに変更）
3. 操作: プログラムの開始
   - プログラム: `python`
   - 引数: `nikkei_daytrade.py --out-dir reports`
   - 開始（作業フォルダ）: リポジトリのパス

## 選定結果を検証する（答え合わせ）

`nikkei_verify.py` は、過去に選んだ銘柄で実際に売買していたらどうなったかを、実際の株価で計算します。
**このスコアに意味があるのかを、1円も使わずに確かめるための機能です。**

### 検証ルール

- 選定した**翌営業日の寄付で等金額ずつ買い、その日の引けで全部売る**
- 往復の手数料+スリッページとして 0.1% を差し引く（`--cost-pct` で変更可）
- **同じ日に日経平均を同じルールで売買した場合と比較する**

3つ目が重要です。相場全体が上がった日は何を買っても儲かるため、日経平均を上回っていなければ
「銘柄を選んだ意味がなかった」ことになります。

### 使い方

GitHubのActionsタブから **「選定結果の検証」→ Run workflow** で実行できます（PCは不要）。
結果は実行後のサマリ画面に表示されます。

ローカルで動かす場合:

```bash
python nikkei_verify.py            # reports/ の全レポートを検証
python nikkei_verify.py --top 3    # 各日の上位3銘柄だけ検証
python nikkei_verify.py --detail   # 1取引ずつ明細を表示
```

### 出力例

```
売買日             銘柄数      平均損益      勝率      日経平均        差
------------------------------------------------------------------------------
2026-08-03        10    +0.42%     60%    +0.31%   +0.11pt
2026-08-04        10    -0.88%     30%    -0.52%   -0.36pt
------------------------------------------------------------------------------

■ 全体
  取引数      : 20 件 (9勝 11敗)
  勝率        : 45.0%
  平均損益    : -0.230% / 取引

■ 日経平均を同じルールで売買した場合との比較
  日経平均    : -0.105% / 日
  差          : -0.125pt

■ 判定
  【判断保留】検証日数が 2 日しかありません。
  20日、できれば60日ためてから判断してください。
```

### 判定の見方

| 表示 | 意味 |
|------|------|
| 判断保留 | 検証日数が20日未満。数字は運の影響が大きく、良くても悪くても意味がない |
| 見送り | 日経平均に負けている、または平均損益がマイナス。銘柄選定に価値が見えない |
| 継続検証 | 日経平均を上回っている。ただし損切りルールが無い状態の数字である点に注意 |

### 検証の限界

以下は**計算に含まれていません**。実際の成績はこれより悪くなります。

- **寄付で必ず約定する前提**です。ストップ高・ストップ安や板が薄い場面では、この価格では買えません
- **損切りがありません**。引けまで持ち切る前提なので、途中でどれだけ含み損を抱えても耐えたことになっています（`--detail` の「最大損」列で実際の下げ幅を確認してください）
- **税金を引いていません**（利益の約20%）
- **サンプルが少ないうちは、勝っていても偶然です**。20日で20%勝ち越すようなことは、コインを投げていても普通に起こります

## 注意事項

- 株価データは Yahoo Finance の公開チャートAPIから取得しています。仕様変更で動かなくなる可能性があります
- 8:45時点では当日の板情報・気配値は取得できません。前営業日終値までの日足がベースです
- 決算発表やニュースによるギャップは日足データには織り込まれません。寄り付き前に別途確認してください
- 本ツールは機械的な抽出であり、投資判断を推奨するものではありません。売買は自己責任で行ってください

# 信用残スクリーナー

JPX公式の「銘柄別信用取引週末残高」（週次PDF）を直近5週分取得し、株価と突き合わせて
2種類の銘柄リストを抽出します。

- **A. 逆行警戒**: 株価が下落しているのに信用買い残が増え続けている銘柄。
  買い方の評価損が膨らみ、戻り局面での返済売り（しこり）で上値が重くなりやすい形。
- **B. 需給良好**: 信用倍率が低く（売り長）買い残も軽い銘柄。
  上昇時に売り方の買い戻し（踏み上げ）が追い風になりやすい形。

## 使い方

```bash
pip install pdfplumber
python margin_screener.py --out-dir reports/margin

# JPXのPDF構造を確認するだけ (デバッグ用)
python margin_screener.py --inspect
```

### 主なオプション

| オプション | デフォルト | 説明 |
|-----------|-----------|------|
| `--weeks` | 5 | 参照する週次データの数 |
| `--top` | 15 | 各リストの掲載数 |
| `--min-weeks` | 3 | A: 買残の最低連続増加週数 |
| `--min-buy-increase` | 15 | A: 期間中の買残増加率の下限（%） |
| `--min-price-drop` | 5 | A: 期間中の株価下落率の下限（%） |
| `--max-ratio` | 1.2 | B: 信用倍率の上限 |
| `--min-turnover` | 3 | 20日平均売買代金の下限（億円） |
| `--out-dir` | なし | レポートの保存先（`YYYY-MM-DD.md` / `.json`） |

## 自動実行

`.github/workflows/margin-screener.yml` により毎週水曜 8:00 JST に実行され、
結果は `reports/margin/` にコミットされます。JPXの銘柄別残高は通常翌週火曜夕方に
公表されるため、その翌朝に最新週まで反映した状態で走ります。

## データソースと注意点

- 信用残: [JPX 銘柄別信用取引週末残高](https://www.jpx.co.jp/markets/statistics-equities/margin/05.html)（毎週末基準・PDF）
- 株価: Yahoo Finance チャートAPI（日足）
- 信用残は週次のため、直近数日の変化は反映されません。機械的な抽出であり投資判断の推奨ではありません。

# メルカリ 価格アラートボット

指定したキーワードと上限価格でメルカリを定期監視し、新着出品をターミナルに表示します。

## 使い方

```bash
python mercari_alert.py <キーワード> <上限価格円> [--interval 秒]
```

### 例

```bash
# Nintendo Switch を ¥20,000 以下で60秒ごとに監視
python mercari_alert.py "Nintendo Switch" 20000

# AirPods Pro を ¥15,000 以下で2分ごとに監視
python mercari_alert.py "AirPods Pro" 15000 --interval 120
```

## 出力例

```
メルカリ監視開始
  キーワード : Nintendo Switch
  上限価格   : ¥20,000
  監視間隔   : 60秒
  停止       : Ctrl+C

初期データ取得中...
既存 30 件を確認。以降の新着を通知します。

============================================================
[14:35:22] 新着 2 件!  「Nintendo Switch」 ¥20,000以下
============================================================
  ¥ 18,000  Nintendo Switch 本体 ジョイコン付き
            https://jp.mercari.com/item/m12345678901
  ¥ 15,500  ニンテンドースイッチ 本体のみ
            https://jp.mercari.com/item/m98765432109
```

## 注意事項

- 監視間隔は最低10秒以上にしてください（サーバー負荷対策）
- Ctrl+C で停止できます
