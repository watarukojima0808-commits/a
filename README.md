# 日経225 デイトレ銘柄スクリーナー

日経225構成銘柄の日足データから、当日のデイトレードに向いた銘柄をスコア順に抽出します。
寄り付き前（8:45頃）に実行し、前営業日終値までのデータで当日の候補を絞り込む想定です。

## セットアップ

初回のみ、構成銘柄リストを日経公式から取得してください（定期入れ替えがあるため、数ヶ月に一度は実行推奨）。

```bash
python nikkei_daytrade.py --update-list
```

リポジトリには `data/nikkei225.csv` にスナップショットが同梱されていますが、
入れ替えが反映されていない可能性があるため、上記の更新を先に実行するのが確実です。

## 使い方

```bash
# 上位10銘柄をターミナルに表示
python nikkei_daytrade.py

# 上位15銘柄、ATR2%以上に絞り、レポートを reports/ に保存
python nikkei_daytrade.py --top 15 --min-atr 2.0 --out-dir reports

# 結果をGmailで自分宛に送る
python nikkei_daytrade.py --out-dir reports \
  --gmail-from you@gmail.com --gmail-to you@gmail.com \
  --gmail-password 'xxxx xxxx xxxx xxxx'
```

### オプション

| オプション | デフォルト | 説明 |
|-----------|-----------|------|
| `--top` | 10 | 表示する上位銘柄数 |
| `--min-atr` | 1.5 | ATR(14)の下限（%）。値幅の出ない銘柄を除外 |
| `--min-turnover` | 20 | 20日平均売買代金の下限（億円）。板の薄い銘柄を除外 |
| `--min-price` | 500 | 株価の下限（円） |
| `--max-price` | 0 | 株価の上限（円、0で無制限） |
| `--out-dir` | なし | Markdownレポートの保存先。`YYYY-MM-DD.md` で出力 |
| `--workers` | 6 | 並列取得数 |
| `--codes-file` | `data/nikkei225.csv` | 銘柄リストCSV（`code,name` 形式） |
| `--update-list` | — | 構成銘柄リストを更新して終了 |

## スコアの内訳（100点満点）

デイトレードで利益機会があるかどうかを、4つの観点で採点しています。

| 配点 | 指標 | 考え方 |
|------|------|--------|
| 40点 | ATR(14) / 株価 | 値幅がなければ利益機会がない。4%以上で満点 |
| 25点 | 前日出来高 / 20日平均 | 出来高急増は当日も値動きが続くサイン。2.5倍で満点 |
| 20点 | 20日平均売買代金 | 板が厚いほど約定が滑らない。1日100億円で満点 |
| 15点 | 5日騰落率の絶対値 | 上下どちらでも「動いている」銘柄を評価。8%で満点 |

上昇・下落の方向は問いません。デイトレでは空売りも使えるため、
「どちらでもいいから動いている」ことを評価する設計です。

## 毎朝自動で実行する（GitHub Actions）

`.github/workflows/nikkei-daytrade.yml` を同梱しています。GitHubのサーバーが平日の朝に実行するため、
自分のPCの電源が入っている必要はありません。publicリポジトリなので無料枠の消費もありません。

### 設定手順

**1. ワークフローをデフォルトブランチに置く**

GitHubの仕様上、スケジュール実行は**デフォルトブランチにあるワークフローしか動きません**。
このブランチをデフォルトブランチにマージしてください。

**2. Gmailアプリパスワードを取得する**

通常のGmailパスワードでは送信できません。2段階認証を有効にしたうえで、
[Googleアカウントのアプリパスワード](https://myaccount.google.com/apppasswords) で16桁のパスワードを発行します。

**3. GitHub Secrets に登録する**

リポジトリの Settings → Secrets and variables → Actions → New repository secret で3つ登録します。

| Secret名 | 値 |
|----------|-----|
| `GMAIL_FROM` | 送信元のGmailアドレス |
| `GMAIL_TO` | 受信したいメールアドレス |
| `GMAIL_PASSWORD` | 手順2で発行した16桁のアプリパスワード |

Secretsは暗号化され、ログにも表示されません。publicリポジトリでも他人から読み取られることはありません。

**4. 動作確認する**

Actions タブ →「日経225 デイトレ候補」→ Run workflow で手動実行できます。
スケジュールを待たずにメールが届くか確認してください。

### 実行タイミング

平日 **8:20 JST**（UTC 23:20）に設定しています。8:45ではなく8:20にしているのは、
GitHubのスケジュール実行が混雑時に5〜20分ほど遅延することがあるためで、
寄り付き（9:00）までに確実にメールが届くようにするための余裕です。

早すぎる・遅すぎる場合は `.github/workflows/nikkei-daytrade.yml` の `cron` を調整してください。
**UTC指定**なので、JSTから9時間引いた値を書きます（曜日も前日にずれます）。

### 実行結果の保存

毎回のレポートは `reports/YYYY-MM-DD.md` としてリポジトリにも自動コミットされます。
過去の選定結果が残るので、後から「このスコアは当たっていたか」を検証できます。

### 注意事項

- **祝日も実行されます。** 日本の祝日判定は入れていないため、休場日には前営業日と同じ内容のメールが届きます
- **60日間リポジトリに動きがないと、GitHubはスケジュール実行を自動停止します。** 毎日のレポート自動コミットで動きは発生しますが、確実に防げる保証はありません。しばらくメールが来ないと感じたらActionsタブを確認してください
- **Yahoo Finance がクラウドのIPを制限する可能性があります。** 取得成功率が60%を下回るとワークフローは失敗し、GitHubから通知メールが届きます。頻発する場合は下記のPC実行に切り替えてください

## 選定結果を検証する（答え合わせ）

`nikkei_verify.py` は、過去に選んだ銘柄で実際に売買していたらどうなったかを、実際の株価で計算します。
**このスコアに意味があるのかを、1円も使わずに確かめるための機能です。**

### 検証ルール

- 選定した**翌営業日の寄付で等金額ずつ買い、その日の引けで全部売る**
- 往復の手数料+スリッページとして 0.1% を差し引く（`--cost-pct` で変更可）
- **同じ日に日経平均を同じルールで売買した場合と比較する**

3つ目が重要です。相場全体が上がった日は何を買っても儲かるため、日経平均を上回っていなければ
「銘柄を選んだ意味がなかった」ことになります。

### 使い方

GitHubのActionsタブから **「選定結果の検証」→ Run workflow** で実行できます（PCは不要）。
結果は実行後のサマリ画面に表示されます。

ローカルで動かす場合:

```bash
python nikkei_verify.py            # reports/ の全レポートを検証
python nikkei_verify.py --top 3    # 各日の上位3銘柄だけ検証
python nikkei_verify.py --detail   # 1取引ずつ明細を表示
```

### 出力例

```
売買日             銘柄数      平均損益      勝率      日経平均        差
------------------------------------------------------------------------------
2026-08-03        10    +0.42%     60%    +0.31%   +0.11pt
2026-08-04        10    -0.88%     30%    -0.52%   -0.36pt
------------------------------------------------------------------------------

■ 全体
  取引数      : 20 件 (9勝 11敗)
  勝率        : 45.0%
  平均損益    : -0.230% / 取引

■ 日経平均を同じルールで売買した場合との比較
  日経平均    : -0.105% / 日
  差          : -0.125pt

■ 判定
  【判断保留】検証日数が 2 日しかありません。
  20日、できれば60日ためてから判断してください。
```

### 判定の見方

| 表示 | 意味 |
|------|------|
| 判断保留 | 検証日数が20日未満。数字は運の影響が大きく、良くても悪くても意味がない |
| 見送り | 日経平均に負けている、または平均損益がマイナス。銘柄選定に価値が見えない |
| 継続検証 | 日経平均を上回っている。ただし損切りルールが無い状態の数字である点に注意 |

### 検証の限界

以下は**計算に含まれていません**。実際の成績はこれより悪くなります。

- **寄付で必ず約定する前提**です。ストップ高・ストップ安や板が薄い場面では、この価格では買えません
- **損切りがありません**。引けまで持ち切る前提なので、途中でどれだけ含み損を抱えても耐えたことになっています（`--detail` の「最大損」列で実際の下げ幅を確認してください）
- **税金を引いていません**（利益の約20%）
- **サンプルが少ないうちは、勝っていても偶然です**。20日で20%勝ち越すようなことは、コインを投げていても普通に起こります

## 注意事項

- 株価データは Yahoo Finance の公開チャートAPIから取得しています。仕様変更で動かなくなる可能性があります
- 8:45時点では当日の板情報・気配値は取得できません。前営業日終値までの日足がベースです
- 決算発表やニュースによるギャップは日足データには織り込まれません。寄り付き前に別途確認してください
- 本ツールは機械的な抽出であり、投資判断を推奨するものではありません。売買は自己責任で行ってください

# エリオット3波入り候補スクリーナー

日経225構成銘柄の日足から、**1波の上昇 → 2波の押し**という形を機械的に検出し、
2波が終わって**3波に移行しようとしている銘柄**をスコア順に抽出します。
大引け後（15:30以降）に実行し、翌日以降のエントリー候補を絞り込む想定です。

エリオット波動では3波が最も伸びやすい波とされているため、
「2波の底で仕込み、1波高値の上抜けで3波に乗る」という狙い方の下準備にあたります。

## 使い方

```bash
# 上位10銘柄をターミナルに表示
python elliott_wave3.py

# 上位15銘柄、レポートを reports/elliott/ に保存
python elliott_wave3.py --top 15 --out-dir reports/elliott

# 1波が12%以上、2波の底から7日以内の銘柄だけに絞る
python elliott_wave3.py --min-wave1 12 --max-age 7
```

銘柄リストは日経225のスクリーナーと共通で `data/nikkei225.csv` を使います。
更新は `python nikkei_daytrade.py --update-list` で行えます。

### 波形の判定ルール

日足の高値・安値からジグザグ（転換点）を引き、直近が **安値 → 高値 → 安値** の並びになっている銘柄を探します。
そのうえで、次を満たすものだけを候補にします。

| 条件 | デフォルト | 理由 |
|------|-----------|------|
| 2波の底 > 1波の起点 | 必須 | **エリオットの絶対ルール**。1波の始点を割ったら、この数え方は成立しない |
| 1波の上昇率 | 8%以上 | 小さすぎる波はノイズと区別がつかない |
| 2波の押し戻し率 | 38.2〜78.6% | 2波は深く押すのが普通。38.2%未満の浅い押しは4波の形に近い |
| 2波の底からの経過 | 1〜15日 | 反発が始まっていて、かつ動き出したばかりであること |
| 現在値 | 2波の底より上、1波高値より下 | まだ高値を抜いていない＝「これから3波」の状態 |
| 2波の戻し | 下げ幅の70%まで | 戻しすぎた銘柄（もう半値戻し以上）は妙味が薄い |
| 転換点の閾値 | 4% または ATRの2.5倍 | 値動きの荒い銘柄ほど閾値を広げ、ノイズを転換点と誤認しない |

1波高値をすでに抜いた銘柄も見たい場合は `--allow-breakout` を付けてください。

### 波形の頑健性チェック（照合）

同じチャートでも、転換点の閾値を変えると波の数え方は変わります。そこで候補ごとに、
**閾値4%固定（チャートツールのエリオット指標に多い設定）でも同じ2波の底が出るか**を照合し、
レポートに `照合 ○ / −` として出しています。

- **○** … 閾値の取り方に依存しない波形。ノイズを1波2波と読んでいる可能性が低い（+10点）
- **−** … その閾値でしか見えない波形。細かい上下動を波として数えている可能性がある

照合に使う閾値は `--cross-swing` で変更できます（`0` で照合なし）。

### 業績チェック

**押し目に見えても、業績悪化の初動ならそのまま下抜けます。** そこで波形の条件を満たした銘柄だけ、
Yahoo Finance から業績を取得し、**実績（直近四半期）** と **来期予想** の2軸で評価します。

**実績** — 直近四半期の前年同期比です。

| 格付け | 条件 | スコア調整 |
|--------|------|-----------|
| ◎ 増収増益 | 利益成長 +10%以上 | +8 |
| ○ 増益 | 利益・売上ともにプラス | +3 |
| △ 減速 | どちらかがマイナス（利益は-10%以内） | -3 |
| ✕ 減収減益 | 利益成長 -10%以下、または増収も増益もなし | -12 |
| ? データなし | 成長率が取得できない | 0 |

**来期** — アナリスト予想EPSの「今期 → 来期」の増減率です。実績が失速していても来期回復予想なら
評価が変わり、逆に実績が良くても来期減益予想なら減点されます。

| 来期予想EPS | スコア調整 |
|------------|-----------|
| +10%以上 | +5 |
| 0%以上 | +2 |
| -10%まで | -3 |
| -10%より下 | -6 |

さらにレポートには、**前回決算がコンセンサスに対して上振れたか下振れたか**（実績EPS vs 予想EPS）と、
**直近4四半期で何回上振れたか**、**通期純利益の4年推移**を載せています。

> ⚠️ 「来期予想」は**アナリストのコンセンサス予想**であって、**会社が出すガイダンス（会社予想）ではありません。**
> Yahoo Finance からは日本企業の会社予想が取れないためです。保守的に出す会社もあれば強気な会社もあるので、
> 会社予想との差は決算短信で確認してください。

`--exclude-bad` を付けると実績 ✕ の銘柄を除外します（**自動実行では有効にしています**）。

**決算発表日**も取得し、7日以内なら警告を出します（`--earnings-warn` で変更可）。
決算をまたぐとギャップで損切り位置を飛ばされるため、2波の底に損切りを置く前提と相性が悪いためです。

業績データは `python yahoo_fundamentals.py 9021 1925` で単体でも確認できます。
`--no-fundamentals` を付ければ、波形だけの判定に戻せます。

### 需給チェック（信用残）

**信用買残が積み上がっている銘柄は、戻り売りで上値が重くなります。** そこで
日本証券金融（日証金）の貸借取引残高を日次で取得し、需給を評価します。
全銘柄分が1つのCSVにまとまっているため、追加のリクエストは1回だけです。

**貸借倍率 = 融資残高（買い方） ÷ 貸株残高（売り方）**

| 貸借倍率 | 状態 | スコア調整 |
|---------|------|-----------|
| 0.8倍未満 | 売り長（踏み上げ余地） | +4 |
| 0.8〜1.5倍 | 融資と貸株が均衡 | +1 |
| 1.5〜3倍 | やや買い長 | 0 |
| 3〜8倍 | 買い長 | -2 |
| 8〜15倍 | 買い長・上値が重い | -4 |
| 15倍超 | 大きく買い長・戻り売り圧力 | -6 |
| 貸株残ゼロ | 売り方不在 | -5 |

これに**買い残の増減**（残高比 -5%以下 +3 / マイナス +1 / 横ばい -1 / +5%以上 -3）と、
**貸借規制**（申込停止・注意喚起なら -3）を加えます。合計で **-12〜+7** の範囲です。

買い残が減っていれば「しこりの整理が進んでいる」、増えていれば「戻り待ちの売りが積み上がっている」
という読み方になります。`python jsf_margin.py 9021` で単体でも確認できます。

> ⚠️ 日証金の貸借残は、**証券会社が日証金から借りた分**であって、東証が公表する信用残そのものではありません。
> 一般信用や、日証金を通さない分は含まれません。方向感を日次で追う用途には十分ですが、
> 正確な信用買残は東証の週次公表（火曜・PDF）を確認してください。データは1営業日遅れです。

### スコアの内訳

**総合 = 波形スコア（100点満点） + 実績調整（-12〜+8） + 来期調整（-6〜+5） + 需給調整（-12〜+7）** です。
波形の質・業績・需給を混ぜず、レポートには内訳を並べて出します。

| 配点 | 指標 | 考え方 |
|------|------|--------|
| 25点 | 押し戻し率 | 50〜61.8%が最も2波らしい。浅すぎ・深すぎは減点 |
| 18点 | 2波の出来高減少 | 押し目で商いが細るのは、売り圧力が枯れているサイン |
| 20点 | 反発の勢い | 5日線回復（7点）／反発後の出来高増（7点）／直近3日の上昇（6点） |
| 15点 | 1波の力強さ | 上昇率（8点）とATR何個分動いたか（7点） |
| 12点 | 地合い | 25日線>75日線（5点）／終値>75日線（4点）／1波が直近安値から出ている（3点） |
| 10点 | 波形の頑健性 | 4%閾値でも同じ2波の底が出るか（上記の照合） |

決算列の `!` は発表が近いという警告です。4番目の銘柄は波形だけなら上位ですが、
減収減益（-12）・来期も減益予想（-3）・買い長で買い残増加（-7）が重なって
総合で22点引かれ、`--exclude-bad` を付ければ除外されます。

`--out-dir` を指定すると、銘柄ごとに以下を含むMarkdownレポートも保存されます。

- 1波・2波の日付と価格（どこからどこまでを何波と数えたか）
- **エントリー目安**: 1波高値の上抜け
- **損切り**: 2波の底の少し下（ここを割ると波動の数え方自体が無効になる）
- **目標**: 2波の底から1波の値幅の1.0倍 / 1.618倍
- リスクリワード比
- 使った閾値と、4%閾値との照合結果
- 業績（売上・利益の前年同期比、営業利益率、ROE、PER、PBR、配当利回り）
- 来期予想EPS（今期→来期）と、前回決算の上振れ/下振れ、通期純利益の4年推移
- アナリストの目標株価と現値比、次回決算日
- 需給（貸借倍率、融資残・貸株残とその増減、回転日数、貸借規制の有無）

### 「底: 未確定」の意味

2波の底からの反発が、まだ転換点の閾値（4%以上など）に届いていない状態です。
**このツールは、あえてこの段階の銘柄を拾います。**

チャートツールのエリオット指標の多くは、転換点を確定するのに「感度」分の足数を待つ設計です
（例: 感度13なら底から13本）。確定を待てば形は綺麗ですが、そのころには値も動いています。
本ツールは未確定の底を拾うことで早く気づける代わりに、
**そのまま下げ続けて「底ではなかった」で終わる候補が混じります**。

早さとダマシの少なさのトレードオフなので、慎重に見たい場合は
「照合 ○ かつ 底 確定」の銘柄だけを見てください。

## 毎日自動で実行する（GitHub Actions）

`.github/workflows/elliott-wave3.yml` を同梱しています。**平日 17:00 JST**（UTC 8:00）に実行し、
結果をメールで送り、`reports/elliott/YYYY-MM-DD.md` としてリポジトリにコミットします。

自動実行では `--exclude-bad` を有効にしているため、**減収減益の銘柄はメールに載りません**。
業績が悪い銘柄も含めて見たい場合は、ワークフローからこのオプションを外してください。

設定はデイトレスクリーナーと共通です（`GMAIL_FROM` / `GMAIL_TO` / `GMAIL_PASSWORD` の3つのSecret）。
[設定手順](#設定手順) を参照してください。すでに設定済みなら、このワークフローの追加だけで動きます。

**スケジュール実行はデフォルトブランチにあるワークフローしか動きません。**
このブランチをデフォルトブランチにマージしてください。

デイトレスクリーナーと違い、日本の休場日には `--require-fresh` により何も送信されません
（当日の日足が存在しないため休場と判定します）。

## チャートツールのエリオット指標と結果が食い違うとき

TradingViewなどの自動カウント指標が「カウント不確定」と出している銘柄を、
本ツールが拾ってくることがあります。ほとんどは次の3つが原因です（優劣ではなく設定差です）。

**1. 転換点の閾値が違う**

指標側は「最小4%」のような固定値が多く、本ツールはATR×2.5（値動きの荒い銘柄ほど広い）です。
たとえば9021 西日本旅客鉄道（2026-08-14時点）はATR 2.87%なので閾値7.2%になり、次のように見え方が変わります。

| 閾値 | 直近の転換点 |
|------|-------------|
| 7.2%（本ツール） | 安値 6/04 2,453 → **高値 7/29 3,236** → **安値 8/06 2,782** |
| 4%（指標側） | 安値 7/22 2,893 → 高値 7/29 3,236 → 安値 8/06 2,782 → 高値 8/07 2,978 → 安値 8/13 2,834 |

4%では 8/07 と 8/13 の小さな上下動も転換点として拾うため、直近が「安値→高値→安値」の
綺麗な1-2波に見えず、カウントが確定しません。この食い違いは **照合 −** として表示されます。

**2. 確定待ちの遅延**

指標側は転換点の確定に感度分の足数を待ちます（感度13なら底から13本）。
底が5本前なら、指標側は構造的にまだ確定できません。本ツールは未確定の底を拾うので、その分早く出ます。

**3. 波の「格」の解釈**

本ツールは直近3つの転換点しか見ないため、**もっと大きな下降の途中の戻り**を1波と数えてしまうことがあります。
指標側が上位の波を追っていると、そもそも数えている波の階層が違います。これは本ツールの明確な弱点です。

指標側の設定に寄せたい場合は `--swing-atr 0 --swing 4` で閾値を4%固定にできます。

## 注意事項

- **エリオット波動のカウントは、そもそも一意に決まりません。** 同じチャートでも人によって数え方が変わります。本ツールの「1波・2波」はジグザグからの機械的な推定であり、正解ではありません
- **2波に見えて、実は下降トレンドの戻りだった、というケースが必ず混じります。** 損切り位置（2波の底）を守ることが前提の使い方になります
- **上昇波動（買い）だけを探します。** 下落の3波（売り）は検出しません
- **「来期」はアナリストのコンセンサス予想で、会社予想ではありません。** 会社が保守的な予想を出す銘柄では、会社予想とかけ離れることがあります
- **一過性の特益・特損は区別していません。** 「増益」に見えても資産売却益ということがあります。最終確認は決算短信で行ってください
- **需給は日証金の貸借残（1営業日遅れ）で見ています。** 東証の信用残（週次）とは対象範囲が違い、一般信用は含まれません。貸借銘柄でない銘柄は需給の判定を行いません（調整0）
- **日本株では成長率が欠損している銘柄があります**（`?` と表示）。この場合スコア調整は行いません
- 株価データは Yahoo Finance の公開チャートAPI、業績データは quoteSummary から取得しています。後者はクッキー認証が必要で、取得に失敗した場合は業績なしで続行します（レポートに `?` が並びます）
- 本ツールは機械的な抽出であり、投資判断を推奨するものではありません。売買は自己責任で行ってください

# MA10（TradingView インジケーター）

移動平均を**最大10本**まで重ねられる TradingView 用インジケーターです（`pine/ma10.pine`）。
1本ごとに「種別・期間・時間足・ずらし・色・太さ」を個別に設定できます。

移動平均だけだと結局は目視判断になるので、実戦で使う周辺機能も一緒に載せてあります。

| 装備 | 内容 |
|------|------|
| 10本のMA | SMA / EMA / WMA / SMMA(RMA) / VWMA / HMA / DEMA / TEMA から個別に選択 |
| マルチタイムフレーム | 各MAに時間足を指定可（5分足チャートに日足の25MAを重ねる、など） |
| パーフェクトオーダー | 表示中のMAが期間順に並んだら背景を色づけ＋ラベル＋アラート |
| ゴールデン/デッドクロス | 任意の2本を指定して矢印表示＋アラート |
| 価格とMAのクロス | 指定した1本に対する終値の上抜け・下抜けを検出＋アラート |
| リボン | 隣り合うMAの間を上下関係で塗り分け |
| 傾きで色替え | 各MAが前バーより上向きか下向きかで色を変える |
| バンド | ボリンジャー（±σ）またはパーセントエンベロープ（±%） |
| 情報テーブル | 期間の短い順に「値・乖離率・傾き」と現在の状態を一覧表示 |

## 導入手順

1. TradingView でチャートを開き、下部の **Pineエディタ** を開く
2. `pine/ma10.pine` の中身をすべて貼り付ける
3. 「チャートに追加」を押す
4. インジケーター名の横の歯車から設定を開く

保存しておけば、以降は「インジケーター → マイスクリプト」から呼び出せます。

## 初期設定

| スロット | 種別 | 期間 | 状態 |
|---------|------|------|------|
| MA1 | SMA | 5 | 表示 |
| MA2 | SMA | 25 | 表示 |
| MA3 | SMA | 75 | 表示 |
| MA4 | SMA | 200 | 表示 |
| MA5〜MA10 | EMA10 / EMA20 / SMA50 / SMA100 / SMA150 / SMA300 | — | 非表示 |

日本株の日足でよく使われる 5・25・75・200 を最初から出しています。
MA5以降はチェックを入れれば増やせます（合計10本まで）。

## 各設定の見方

**MA 1〜10**（グループごとに2行）

- 1行目 … 表示ON/OFF ／ 種別 ／ 期間
- 2行目 … 色 ／ 太さ（1〜4） ／ 時間足（空欄でチャートと同じ） ／ ずらし（正で右、負で左）

**共通設定**

- ソース … 全MA共通の計算元（終値・始値・hlc3 など）
- 傾きで色を変える … ONにすると各MAの色設定を無視し、上向き/下向きで色分け

**パーフェクトオーダー**

表示中のMAを期間の短い順に並べ、`短期 > 中期 > 長期`（下降はその逆）に整列している状態を検出します。

- 最低本数 … この本数以上表示されているときだけ判定（初期値3）
- 価格の位置も条件に入れる … 上昇なら終値が最短期MAより上、下降なら下、を条件に追加

**クロス**

- 速いMA / 遅いMA … スロット番号（1〜10）で指定。初期値は MA1(5) と MA2(25)
- 価格とMAのクロス … 終値が指定スロットのMAを抜けたら丸印

## アラートの設定方法

チャート右上の時計マーク（アラート）→ 条件に「MA10」を選ぶと、次の7つから選べます。

- ゴールデンクロス / デッドクロス
- パーフェクトオーダー成立（上昇） / （下降）
- パーフェクトオーダー崩れ
- 価格がMAを上抜け / 下抜け

「バーの終値で」を選ぶと、確定足だけで通知されます（ダマシが減ります）。

## 注意事項

- Pine Script **v6** で書いています。TradingView の現行環境ならそのまま動きます
- **上位足のMAを指定した場合、その足が確定するまで値は動き続けます。** 先読み（lookahead）は切ってあるので過去の見え方が変わることはありませんが、リアルタイムでは上位足の未確定値を見ていることになります
- **VWMA は出来高が必要です。** 出来高データのない銘柄・指数では表示されません
- リボンは**スロット番号が隣り合うMAの間**を塗ります。きれいに出したい場合は、期間の短い順にスロットを並べてください
- パーフェクトオーダーは「表示中のMAだけ」で判定します。MAを増減させると判定結果も変わります
- 移動平均は過去の価格の平均であり、遅行指標です。本インジケーターは売買を推奨するものではありません
